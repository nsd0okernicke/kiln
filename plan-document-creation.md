# Plan: CLAUDE.md / copilot-instructions.md Generation Redesign

## Problem Statement

The current `Write-GeneratedCLAUDEmd` function in `kiln.ps1` produces a document with three sources of truth that contradict or duplicate each other:

1. **Hardcoded PS1 strings** — "Receiving Messages" section, "Runtime Paths" section, SQL INSERT template
2. **Template files** — `workflow.md`, `engineering.md`, `project.md`, role files
3. **Role files themselves** — each role has `## Message Loop` which repeats what `workflow.md` already says about the message queue

Specific redundancies in the current output:
- `workflow.md` §"Check Your Inbox" + role file §"Message Loop" step 1 + hardcoded "Receiving Messages" in PS1 → three places say "call wait_for_message()"
- `workflow.md` §"Send a Message" + role file §"Message Loop" step 7 + hardcoded SQL INSERT in PS1 → three places describe the handoff INSERT
- `workflow.md` merge rule + role file §"Message Loop" step 2 → both say "merge the sender's commit"
- `engineering.md` contains project-specific tech stack (FastAPI, PostgreSQL, RabbitMQ, Python) that belongs in `project.md`

Additional problem: `wait_for_message()` is Claude-specific. Copilot and other agents need pull-mode instructions. The generator has no agent-awareness beyond the output filename.

---

## Decisions

| # | Question | Decision |
|---|----------|----------|
| 1 | Role file detail level | Full role file (minus Message Loop) goes in the generated doc. No Work Phase extraction in first iteration. |
| 2 | Handoff routing table | Lives in `workflow.md`; PS1 reads it from there to populate `{{HANDOFF_TARGET}}` |
| 3 | Startup greeting | Always tied to `mode=manual`; hardcoded in `loop-manual-*.md` template |
| 4 | Merge commands | Inlined in loop template (self-contained, no cross-reference to `workflow.md`) |
| 5 | engineering.md scope | Generic principles only; project-specific tech stack moves to `project.md` |

---

## Goals

1. **Template-only generation** — zero prose hardcoded in `kiln.ps1`; the script only does variable substitution and file concatenation
2. **Agent mode** — configurable in `profiles.json` per terminal; controls which loop block goes first and whether the agent interacts with the user
3. **Document structure** — loop block first → runtime section → constitution → full role content
4. **No redundancy** — each rule lives in exactly one template file
5. **Agent-type awareness** — Claude and Copilot get different loop and runtime templates

## New Document Structure

```
<!-- Auto-generated by kiln.ps1 on <timestamp> -->
<!-- DO NOT EDIT MANUALLY -->

[1. LOOP BLOCK]
    mode=auto  → loop-auto-claude.md  / loop-auto-copilot.md
    mode=manual → loop-manual-claude.md / loop-manual-copilot.md

[2. RUNTIME SECTION]
    runtime-claude.md / runtime-copilot.md
    (role, branch, DB path, SQL INSERT — with {{VARIABLE}} substitution)

[3. WORKFLOW CONSTITUTION]
    workflow.md — trimmed (message queue §§ removed; loop block covers them)

[4. ENGINEERING CONSTITUTION]
    engineering.md — generic principles only

[5. PROJECT CONSTITUTION]
    project.md — project-specific content + tech stack decisions

[6. ROLE CONTENT]
    roles/<role>.md — WITHOUT the ## Message Loop section
    Contains full ownership, standards, quality gates, TDD rules, etc.
```

The Loop Block is first because it is the most critical behavioral instruction. Under context pressure the LLM reads the top of the document most reliably. The full role content comes last because it is the most stable and role-specific reference material.

### Template Selection Matrix

The generator selects exactly one loop template and one runtime template per agent, based on `mode` × `agent`:

| mode \ agent | claude | copilot |
|---|---|---|
| `auto` | `loop-auto-claude.md` + `runtime-claude.md` | `loop-auto-copilot.md` + `runtime-copilot.md` |
| `manual` | `loop-manual-claude.md` + `runtime-claude.md` | `loop-manual-copilot.md` + `runtime-copilot.md` |

Key behavioral differences between claude and copilot variants:

| Aspect | claude | copilot |
|---|---|---|
| Message receipt | `wait_for_message()` — blocks in MCP server | `read_query` poll loop — returns immediately |
| Mark delivered | Done atomically inside `channel.py` | Agent must `UPDATE status='delivered'` explicitly |
| MCP servers | `kiln-db` + `kiln-channel` | `kiln-db` only |
| Idle behavior | Blocked inside tool call — zero CPU | Agent sleeps 15s between polls |

## Variable Substitution

Templates use `{{VARIABLE}}` placeholders. The PS1 replaces them at generation time:

| Placeholder | Value | Resolved by |
|-------------|-------|-------------|
| `{{ROLE}}` | e.g. `coder` | Profile terminal config |
| `{{ROLE_UPPER}}` | e.g. `CODER` | PS1 `.ToUpper()` |
| `{{BRANCH}}` | e.g. `main` | `git rev-parse --abbrev-ref HEAD` |
| `{{DB_PATH}}` | Absolute path to `messages.db` | `$STATE_DIR` |
| `{{WORKTREE}}` | Leaf name of worktree path | `Split-Path -Leaf $WorktreePath` |
| `{{HANDOFF_TARGET}}` | e.g. `refactorer` | Read from routing table in `workflow.md` |
| `{{COMMIT_FORMAT}}` | e.g. `[Coder] <name> - TDD impl of <what>` | PS1 hashtable (see below) |

### Handoff Routing Table (in `workflow.md`)

A new section in `workflow.md` defines the canonical routing:

```markdown
## Handoff Routing

| Role | Sends to |
|------|----------|
| specifier | coder |
| coder | refactorer |
| refactorer | architect |
| architect | specifier |
| selftest | selftest |
```

The PS1 parses this table at startup and uses it to populate `{{HANDOFF_TARGET}}` for each role's generated document.

### Commit Format Table (PS1 hashtable)

Commit format strings are role-specific data — short enough to live in the PS1 rather than a separate file:

```powershell
$CommitFormats = @{
    "specifier"  = "[Specifier] <feature name> - <what was specified>"
    "coder"      = "[Coder] <feature name> - TDD implementation of <what>"
    "refactorer" = "[Refactorer] <feature name> - <quality gate results>"
    "architect"  = "[Architect] <feature name> - <structural changes made>"
    "selftest"   = "[Selftest] <what was tested>"
}
```

## Loop Block Templates

### `loop-auto-claude.md`

Step 2 inlines the git commands. Step 4 is generic — the full role rules follow in the Role section.

```markdown
## Message Loop

Repeat this sequence indefinitely. **Do not stop after completing work —
the loop is not complete until the handoff is sent (step 7).**

1. **Wait** — call `wait_for_message()` from the `kiln-channel` MCP server.
   If it returns `{"received": false}`, call it again immediately.

2. **Merge** — extract the `Branch:` and `Commit:` fields from the handoff message, then run:
   ```sh
   git merge <commit-hash>
   ```
   This merge commit becomes the squash anchor you will need in step 6.

3. **Log received** — append a logbook.md entry:
   - Timestamp (`YYYY-MM-DD HH:MM:SS`)
   - Complete handoff message content
   - One-line description of what you will do

4. **Work** — apply your role rules. The Role section below defines your specific
   work process, quality gates, and standards. For system-communication-test messages,
   forward as-is to `{{HANDOFF_TARGET}}` and skip steps 5–7.

5. **Log sent** — append a logbook.md entry:
   - Timestamp
   - Brief summary of the handoff you are about to send
   This entry must be committed as part of the squash in step 6.

6. **Squash** — squash all your commits since the merge commit into one:
   ```sh
   LAST_MERGE=$(git log --merges -1 --format="%H")
   git reset --soft "${LAST_MERGE:-$(git rev-list --max-parents=0 HEAD)}"
   git commit -m "{{COMMIT_FORMAT}}"
   ```

7. **Send handoff** — run the SQL in the Runtime section below (write_query).
   Then verify: `SELECT id FROM messages WHERE sender='{{ROLE}}' AND branch='{{BRANCH}}' ORDER BY created_at DESC LIMIT 1`
   If no row is found, INSERT again before returning to step 1.

8. Return to step 1.
```

## New Generation Algorithm in `kiln.ps1`

```powershell
# Routing table — read from workflow.md §"Handoff Routing" at startup
# PS1 parses the markdown table once and stores in a hashtable
$HandoffTargets = Read-HandoffRoutingTable (Join-Path $KILN_DIR "constitution" "workflow.md")

# Commit format strings — role-specific data, lives in PS1
$CommitFormats = @{
    "specifier"  = "[Specifier] <feature name> - <what was specified>"
    "coder"      = "[Coder] <feature name> - TDD implementation of <what>"
    "refactorer" = "[Refactorer] <feature name> - <quality gate results>"
    "architect"  = "[Architect] <feature name> - <structural changes made>"
    "selftest"   = "[Selftest] <what was tested>"
}

function Write-GeneratedCLAUDEmd {
    param(
        [int]$Index,
        [string]$Role,
        [string]$WorktreePath,
        [string]$Agent = "claude",
        [string]$Mode  = "auto"
    )

    # 1. Resolve output path
    $outPath = if ($Agent -eq "copilot") {
        Join-Path $WorktreePath ".github" "copilot-instructions.md"
    } else {
        Join-Path $WorktreePath "CLAUDE.md"
    }

    # 2. Load template blocks in order
    $loopBlock    = Get-KilnTemplate "loop-$Mode-$Agent"
    $runtimeBlock = Get-KilnTemplate "runtime-$Agent"
    $workflow     = Get-KilnConstitution "workflow"
    $engineering  = Get-KilnConstitution "engineering"
    $project      = Get-KilnConstitution "project"
    $roleBlock    = Get-KilnRole $Role   # full file minus ## Message Loop section

    # 3. Build substitution map
    $subs = @{
        "{{ROLE}}"           = $Role
        "{{ROLE_UPPER}}"     = $Role.ToUpper()
        "{{BRANCH}}"         = $CurrentBranch
        "{{DB_PATH}}"        = ($dbPath -replace '\\', '\\')
        "{{WORKTREE}}"       = (Split-Path -Leaf $WorktreePath)
        "{{HANDOFF_TARGET}}" = $HandoffTargets[$Role]
        "{{COMMIT_FORMAT}}"  = $CommitFormats[$Role]
    }

    # 4. Render and concatenate
    $blocks = $loopBlock, $runtimeBlock, $workflow, $engineering, $project, $roleBlock
    $body   = ($blocks | ForEach-Object { Apply-Substitutions $_ $subs }) -join "`n`n---`n`n"

    # 5. Write with header
    $header = "<!-- Auto-generated by kiln.ps1 on $(Get-Date -Format 'yyyy-MM-dd HH:mm:ss') -->`n"
    $header += "<!-- DO NOT EDIT MANUALLY -->`n`n"
    Set-Content $outPath ($header + $body) -Encoding UTF8
}

# Helper: load from kiln/templates/
function Get-KilnTemplate([string]$Name) {
    Get-Content (Join-Path $KILN_DIR "templates" "$Name.md") -Raw -ErrorAction Stop
}

# Helper: load from kiln/constitution/
function Get-KilnConstitution([string]$Name) {
    Get-Content (Join-Path $KILN_DIR "constitution" "$Name.md") -Raw -ErrorAction Stop
}

# Helper: load role file, strip ## Message Loop section
function Get-KilnRole([string]$Role) {
    $raw = Get-Content (Join-Path $KILN_DIR "roles" "$Role.md") -Raw -ErrorAction Stop
    # Remove the ## Message Loop section (from heading to next ## heading or EOF)
    $raw -replace '(?ms)^## (Message Loop|Interaction Loop).*?(?=^## |\z)', ''
}

# Helper: replace all {{KEY}} placeholders
function Apply-Substitutions([string]$Text, [hashtable]$Map) {
    foreach ($key in $Map.Keys) {
        $Text = $Text.Replace($key, $Map[$key])
    }
    $Text
}

# Helper: parse Handoff Routing table from workflow.md
function Read-HandoffRoutingTable([string]$Path) {
    $table = @{}
    $content = Get-Content $Path -Raw
    # Match rows in the | Role | Sends to | table
    $content | Select-String '^\|\s*(\w+)\s*\|\s*(\w+)\s*\|' -AllMatches |
        ForEach-Object { $_.Matches } |
        ForEach-Object { $table[$_.Groups[1].Value] = $_.Groups[2].Value }
    $table
}
```

$varMode = "TERMINAL_${i}_MODE"
$mode = Get-Variable -Name $varMode -ValueOnly -ErrorAction SilentlyContinue
if ([string]::IsNullOrEmpty($mode)) { $mode = "auto" }
$global:MODES += $mode
```

And in the profile-loader, map `"mode"` from each terminal entry to `TERMINAL_${i}_MODE`.
